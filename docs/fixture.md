# Large offline fixture

`public/fixtures/large.json` is a committed, deterministic **synthetic** dataset for developing the LootTown UI. It is not a DevLoot database seed, GitHub import, or current API response. No real accounts, photos, URLs, or repository records are used.

## Reproduce and inspect

With Node 24 and `npm ci`:

```sh
npm run seed:generate
npm test
npm run dev
```

Open `http://localhost:5174/?fixture=large`; the selector chooses one of 40 venues. The default `/` keeps the three-person demo and does not fetch the large JSON. The Docker development service serves the same checked-in file because the source tree is mounted. A static image needs a rebuild to include regenerated bytes.

`npm run seed:generate -- --seed another-name --out work/another.json` exports a separate reproducible scenario. The default seed is `loottown-fixture-v1`. The generator uses a fixed string hash and seeded pseudo-random sequence; it does not use `Math.random`, the clock, network calls, or runtime locale for IDs, memberships, or counts. `npm test` verifies that the checked-in JSON equals the default generator output byte for byte. Do not commit alternate output under `work/`.

## Format and measured scale

The envelope is `{fixtureVersion:1,seed,venues,repositories,communityRepositories}`. Each `venues[]` item is **exactly the proposed `VenueV1` shape** validated by `parseVenueV1`; see [contracts](contracts.md). The sidecar `repositories[]` has fictitious `{id,slug}` rows and `communityRepositories[]` links `{communityId,repositoryId}` to model the many-to-many association. These sidecars do not add unsupported fields to `VenueV1` and are not a claim that the public DevLoot API serves this envelope.

Default output has 40 communities, 15,866 community-person memberships, 5,645 globally distinct fictional person IDs, 168 repository records, and 207 community-repository links. Every community has 213–574 unique members and 3–7 linked repositories; some repository IDs and person IDs appear across communities. No person repeats within a community. The five approved commit bands occur across memberships as follows: base 3,102; accessory 3,114; elaborate 3,211; special 3,207; veteran 3,232. The file is 1,715,905 bytes.

The person pool has 6,000 potential synthetic identities. Handles start with `loottown-fixture-person-`; numeric IDs live in reserved-looking high ranges only to keep fixture records visually distinct. They are **not reserved by GitHub or DevLoot**, and must never be resolved as real profiles. A person shared between communities can have different `communityCommitCount` values, because the count is scoped to one community. Counts are generated directly as synthetic deduplicated community aggregates; they are not computed by summing fake per-repository activity. `coverage.complete:true` only describes the closed fixture generation, and `lastSyncedAt:null` means no provider sync occurred.

The preview displays one selected venue at a time, with at most 6 placeholder 3D characters and 12 text cards. It reports the total membership of the selected venue separately. The 40-venue dataset does not implement the future global map, a production crowd renderer, live presence, or a frame-rate guarantee. The real integration still requires the DevLoot projection and attribution policy tracked in backlog tasks 01–03.

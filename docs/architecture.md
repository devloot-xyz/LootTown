# Architecture decision: small browser scene

Status: accepted for the technical base, 2026-11-03. Revisit when the DevLoot host upgrades React.

Use TypeScript + React 18 + React Three Fiber 8 + Three.js + Vite 6, with npm and Node 24. The DevLoot client currently uses React 18 and Node 24. npm registry peers checked on 2026-11-03: Fiber 8.18.0 accepts `react`/`react-dom >=18 <19`; Drei 9.122.0 accepts React 18 and Fiber 8. This line can be embedded later as a React component without forcing a host upgrade. Fiber 9 targets React 19; Fiber 10 alpha is not the baseline. Exact versions and the lockfile make the base reproducible. A host integration must still test bundling and dependency deduplication in DevLoot's real build.

React handles the text UI and state; Fiber lets scene objects follow React component lifecycle. Pure Three.js would reduce React-specific dependencies but require manual lifecycle and UI synchronization. Babylon.js supplies a fuller engine and animation toolkit, but would add a second scene/component model for this React host. No comparative FPS benchmark was run, so none is claimed. Vite provides a fast standalone dev shell. We do not add Next.js, a new backend, an editor service, or a monorepo.

Source boundaries are intentionally small: `domain` contains rules; `demo` contains fictional input; `scene` renders geometry; `App` renders text controls and fallback. The future DevLoot adapter belongs behind a versioned normalized venue contract. The standalone build must use only verified public reads and a real CORS allowance from DevLoot; a same-origin host integration can avoid cross-origin requests. Never place GitHub tokens or wallet secrets in browser config. UI selection events can be callbacks (`selectCommunity`, `selectPerson`, `openBounty`), with navigation and authorization handled by DevLoot. No endpoint called `/loottown` exists in the inspected API.

GLB/glTF is the target asset format. Blender is optional for creators. Each asset needs source, author, license, attribution, modifications, triangle/texture budget, rig and animation names in a manifest. The demo contains only original procedural geometry. GitCity (srizzon/git-city) is AGPL-3.0; it is an idea reference only and no code or assets are copied.

Use `prefers-reduced-motion`, a motion control, readable DOM equivalents, keyboard-operable navigation, and a WebGL-unavailable view. The initial scene has three placeholders and does not prove crowd scale. `InstancedMesh` helps repeated static meshes, not thousands of independently animated skinned avatars. Before crowd growth, measure draw calls, frame time, memory and load time across target devices; then define visibility caps, LOD, sampling and animation budgets. Avoid asserting a target FPS without measurement.
